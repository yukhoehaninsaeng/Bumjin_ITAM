# VPN·NAS 계정 기능 통합

## 화면

| 메뉴 | 기능 |
| --- | --- |
| 관리자 → VPN·NAS 계정 → VPN 권한 | 상시/기간 권한 등록·수정, LDAP 반영/재시도, 해제 |
| 관리자 → VPN·NAS 계정 → NAS 비밀번호 초기화 | LDAP 사용자 검색, 관리자 비밀번호 재확인, 임시 비밀번호 한 번 표시 |
| 관리자 → VPN·NAS 계정 → 그룹웨어 VPN 결재 | 완료 문서 조회, 사용자/기간 검토 후 권한 등록, 제외/처리 상태 보존 |
| 관리자 → VPN·NAS 계정 → 처리 이력 | 등록·변경·해제·반영·비밀번호 변경 결과와 변경자/시각 |
| 직원 포털 → NAS 계정·VPN | 본인 권한 기간 확인, 현재 비밀번호 확인 후 새 비밀번호로 변경 |
| 관리자 설정 → VPN·NAS | 그룹 DN/멤버 속성, 관리 그룹, 쓰기 스위치, 그룹웨어 연동, VPN 안내 URL |

관리 기능은 GLOBAL system_admin만 사용할 수 있습니다. 직원은 본인 계정과 본인 VPN 기간만 확인·변경합니다. 화면에서 입력한 계정명으로 비밀번호 변경 대상을 바꾸지 않습니다.

## 1. 최신 코드 적용

기존 `platform/config/settings.py`와 `.settings.key`를 유지하고 코드를 업데이트합니다.

```powershell
cd 'C:\Users\BJE\Desktop\AI_PJT\Bumjin_ITAM-main\platform'
$env:ITAM_DEBUG = '1'
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
```

0006 migration은 VPN 권한·알림·결재 상태 테이블을 추가합니다. PostgreSQL에서는 세 테이블의 RLS를 켭니다. 서버 DB 계정은 테이블 소유자/BYPASSRLS여야 하며 Supabase 공개 정책을 추가하지 않습니다.

기존 그룹웨어 멤버/LDAP 계정 동기화를 완료해야 사용자 선택이 가능합니다. LDAP uid·불변 고유 ID가 연결된 계정만 사용합니다. 표시 이름으로 매칭하지 않습니다.

## 2. 연결 설정과 테스트 계정 검증

관리자 설정 → LDAP 연결에서 기존 LDAPS 호스트·Base DN·Bind DN·비밀번호·신뢰 CA를 설정하고 연결 테스트합니다. 실제 그룹 및 비밀번호를 수정할 수 있는 계정 권한이 필요합니다.

관리자 설정 → VPN·NAS:

- LDAP 그룹 Base DN: 기존 NAS의 `cn=groups,실제 Base DN`. 비워두면 위 값을 사용합니다.
- 그룹 멤버 속성: 제공한 시스템은 **member**(사용자 DN)입니다. 서버가 memberUid를 사용하면 명시적으로 선택합니다.
- 관리 그룹: `00. VPN_User_Always|01. VPN_User_Period`가 기본입니다. `|`로 구분한 정확한 그룹 이름만 변경할 수 있습니다. administrators 같은 그룹은 기본 관리 목록에 없습니다.
- VPN 그룹 쓰기 / NAS 비밀번호 변경: 기본 꺼짐. 먼저 테스트 계정을 연결하고 테스트할 기능만 켜세요.
- 그룹웨어 VPN 대상 그룹: `01. VPN_User_Period` 기본값.
- 그룹웨어 URL: HTTPS 원점 주소. 사용자/비밀번호는 저장 시 암호화합니다. 저장한 세션 쿠키를 선택적으로 사용할 수 있으며, 쿠키가 비어 있으면 제공한 `/api/login` 방식으로 로그인합니다. 로그인한 쿠키는 해당 조회 작업 메모리에서만 사용하고 파일에 저장하지 않습니다.
- VPN 내부/외부 안내 주소: 직원 포털에서 링크로 표시합니다.

SMTP는 기존 관리자 설정을 사용합니다. 비밀번호 자체는 메일에 보내지 않으며, 변경 완료 사실과 VPN 기간/만료 예정 알림만 보냅니다.

실제 NAS에서 비밀번호 변경/로그인·VPN 그룹 반영이 정상인지 **테스트 계정 한 명으로 먼저 검증**하세요. 사용자 DN/고유 ID가 일치하지 않거나 root/admin/administrator, 서비스 Bind 계정 또는 Django superuser 계정이면 비밀번호 변경을 차단합니다. 기존 관리자는 이 웹 기능으로 NAS 관리 서비스 계정을 초기화하지 않습니다.

## 3. 기존 데이터 이관

서버를 중지하고 DB·CSV 원본을 백업합니다. 아래 파일들을 로컬 `platform\data\ldap-legacy`에 복사합니다.

- ldap_expiry.csv
- ldap_history.csv
- gw_processed.json
- gw_excluded.json

**먼저 미리보기:**

```powershell
.\.venv\Scripts\python.exe manage.py import_directory_legacy --leases '.\data\ldap-legacy\ldap_expiry.csv' --history '.\data\ldap-legacy\ldap_history.csv' --processed '.\data\ldap-legacy\gw_processed.json' --excluded '.\data\ldap-legacy\gw_excluded.json'
```

제공된 파일 기준 권한 124건(상시 77·기간 47), 이력 399건, 처리/제외 ID 합집합 232개입니다. 제외 ID 11개는 처리 ID 목록과 중복되며 제외 상태를 우선 보존합니다.

`unmapped_or_unlinked`는 기존 Employee의 directory_uid/groupware_uid와 정확히 연결되지 않았거나 LDAP 불변 ID가 없는 건수입니다. 해당 행은 삭제하지 않고 미연결 권한으로 보관하며 LDAP에 쓰지 않습니다. LDAP 동기화 후 동일 uid의 권한을 화면에서 수정·저장하면 연결할 수 있습니다. 다른 uid로 자동 이동하지 않습니다.

건수를 확인한 후 같은 명령에 `--apply`를 붙입니다. **이 단계는 DB 이관만 수행하며 실제 LDAP·메일에 접속하지 않습니다.** 재실행 시 기존 uid/그룹 레코드를 덮어쓰지 않고 이력 해시·문서 ID로 중복 방지합니다.

`9999-12-31`은 상시 권한으로 변환합니다. 이력의 원본 action_date는 원본 문자열로 보존하고 이관 자체 시각은 UTC로 기록합니다. 원래 시간대를 추측해 과거 로그 시각을 재작성하지 않습니다.

올려준 py 파일, 설정, 세션, 로그 파일은 직접 실행하거나 운영 폴더에 복사할 필요가 없습니다. 실제 비밀번호·쿠키·원본 인사 CSV·로그는 저장소에 올리지 않았습니다. `gw_session.json`은 자동 이관하지 않습니다. 기존 로그에는 인증 정보가 포함될 수 있으므로 원본 백업으로 관리하고, 이관은 명시된 CSV/ID JSON에 한정합니다.

## 4. 자동 시작·만료·알림 처리

새 시스템을 검증하는 동안 기존 스케줄러의 쓰기 작업을 함께 돌리지 마세요. 먼저 새 작업의 미리보기를 확인합니다.

```powershell
# 날짜·매핑 기준으로 변경 필요 건수만 출력. LDAP·메일 변경 없음
.\.venv\Scripts\python.exe manage.py process_directory_access

# 실제 반영 1회 (쓰기 스위치도 켜져 있어야 함)
.\.venv\Scripts\python.exe manage.py process_directory_access --apply

# 5분마다 시작/만료 반영과 알림 처리
.\.venv\Scripts\python.exe manage.py process_directory_access --apply --watch --interval 300
```

운영 서버에서는 위 작업을 단일 systemd/Docker 프로세스로 실행하거나 NAS 작업 스케줄러에 단발 명령을 등록합니다. 서버 이전 시 `.settings.key`와 DB 연결 설정을 함께 이전해야 합니다.

- 시작일 00:00부터 사용 가능, 만료일 당일 23:59까지 유효하며 다음 날 그룹에서 제외합니다. 날짜 기준은 관리자 설정 시간대입니다. 최대 실제 반영 지연은 작업 주기와 NAS 연결 상태에 따라 달라집니다.
- 상시 권한은 기간 만료로 해제하지 않습니다. 비활성/퇴사 사용자는 추가하지 않고, 기존 연결을 확인할 수 있으면 관리 대상 VPN 그룹을 해제합니다.
- 해제/만료 시 **VPN 그룹 멤버십만 변경**합니다. NAS 사용자 자체를 비활성화하거나 자산/티켓 이력을 삭제하지 않습니다. 기존 스크립트가 description에 적던 DISABLED 문구는 계정 비활성화로 취급하지 않습니다.
- LDAP 오류는 실패 코드와 함께 권한 레코드를 보존하고 다시 시도합니다. 만료 실패를 성공으로 기록하거나 행을 삭제하지 않습니다.
- 만료 5일·1일 전에 한 번씩 알림을 대기열에 넣습니다. 메일 발송 실패 시 최대 5번 재시도하며 메일 알림이 꺼져 있으면 대기합니다. 이 알림 대기열은 process_directory_access가 처리하며 티켓 메일 worker와 별도입니다.
- NAS에서 외부 도구로 그룹을 바꾸면 화면 기록과 달라질 수 있습니다. `NAS 반영 / 재시도`로 실제 멤버십을 다시 확인·반영하세요. 기본 작업은 변경 대기/실패 및 날짜에 따라 필요한 레코드를 처리합니다.
- 그룹에서 제외해도 이미 연결된 VPN 세션의 즉시 강제 종료까지 보장하지 않습니다. VPN 서버가 언제 그룹 권한을 다시 확인하는지 실제 환경에서 확인하세요.

테스트 계정 검증·이관 건수 대조·미리보기 후 새 작업자로 전환합니다. 기존 expiry/gw_sync 스케줄러는 중복 쓰기를 막기 위해 전환 시 중지하고 원본/스케줄 설정은 복구용으로 보존하세요.

## 5. 비밀번호 처리

관리자는 사용자 선택 → 초기화 사유 → 현재 관리자 비밀번호 재확인 → 초기화 실행. 안전한 난수 임시 비밀번호(20자)를 한 번만 반환하고 마스킹된 입력란에 표시합니다. 닫으면 입력값을 지우며 이력/DB/메일에는 비밀번호를 저장하지 않습니다. 사용자가 본인 포털에서 새 비밀번호로 바꾸도록 안내합니다. 서버가 강제로 다음 로그인 변경을 요구하는 기능은 설정하지 않습니다.

직원은 현재 LDAP 비밀번호를 실제 bind로 검증한 뒤 새 비밀번호를 설정합니다. 새 비밀번호는 최소 12자이고 Django/LDAP 정책을 따릅니다. LDAP 고유 ID 검증 후 userPassword 속성만 수정합니다. 다른 사용자의 ID를 요청에 넣어도 변경 대상을 바꾸지 않습니다.

변경 후 Django 세션 인증 해시를 바꿔 다른 웹 세션은 다음 요청 시 해제합니다. 본인 변경 시 현재 웹 세션은 유지합니다. NAS/VPN의 이미 열린 별도 세션을 강제 종료하지는 않습니다. 운영은 HTTPS로만 비밀번호 요청을 허용하며 개발 DEBUG 모드에서만 로컬 HTTP를 허용합니다.

LDAP 변경 직후 DB 저장/알림 장애가 나면 원격 비밀번호 변경과 DB는 한 트랜잭션으로 되돌릴 수 없습니다. 실패 메시지가 나온 경우 실제 NAS 상태를 확인한 뒤 재시도하세요. LDAP 오류 상세나 비밀번호를 로그로 남기지 않습니다.

## 6. 그룹웨어 결재

제공한 todoviewer와 document API로 결재 완료(APPROVAL/COMPLETE) VPN 문서를 조회합니다. 100건씩 최대 10페이지를 조회하며 기존 문서 ID는 재처리하지 않습니다. 세션이 만료되면 설정의 세션 쿠키를 갱신하거나 쿠키를 비워 계정 로그인 방식을 사용하세요. 인증서 검증을 유지하고 자격 증명이 다른 호스트로 전송되는 리다이렉트를 따르지 않습니다.

명시된 요청 기간의 두 날짜만 파싱합니다. 날짜 누락·역전·90일 초과 시 검토 대상으로 남기며 자동 30일 권한을 부여하지 않습니다. 이름/메일 추정 매핑 없이 관리자가 정확한 LDAP 사용자를 선택해야 권한 대기열에 등록됩니다. 기존 기간과 겹치거나 연속한 기간만 연장하며 떨어진 기간 사이를 임의로 허용하지 않습니다. 날짜를 확인할 수 없는 문서는 수동 권한 등록 후 제외 처리합니다.

이 통합 버전은 결재 조회/검토를 화면에서 실행합니다. 기존처럼 이름 추정과 기본 기간으로 무인 권한 부여하는 동작은 사용하지 않습니다. 그룹웨어 API가 바뀌거나 CAPTCHA/MFA가 필요하면 제공자 인증 방식에 맞춰 추가 조정이 필요합니다.

## 검증 범위

임시 SQLite에서 실제 CSV/ID JSON의 이관·재실행 중복 방지와 모의 LDAPS·SMTP/API 테스트를 수행했습니다. 실제 NAS 비밀번호/그룹·그룹웨어·Windows 스케줄러·PostgreSQL 동시 작업자 검증은 수행하지 않았습니다. 운영 서비스에 접속하거나 업로드된 세션/비밀번호로 로그인하지 않았습니다.


## 비밀번호 분실자용 공개 페이지

로그인 화면의 **비밀번호를 잊으셨나요? · NAS 비밀번호 재설정** 또는 `/password-recovery`를 사용합니다. 현재 비밀번호를 몰라도 계정 ID와 등록된 회사 이메일이 일치하면 30분 유효 일회용 링크를 보냅니다. 받은 메일의 **비밀번호 재설정** 버튼에서 새 비밀번호를 입력합니다.

관리자 설정 → VPN·NAS에서 **이메일 비밀번호 재설정 사용**, **NAS 비밀번호 변경 사용**을 켜고 SMTP 발송·프로그램 접속 주소·서버 암호화 키를 설정해야 합니다. 복구 대상은 연결된 활성 LDAP 사용자이며 로컬 itamadmin/Django superuser, root/admin/administrator 및 서비스 Bind 계정은 이 흐름의 대상이 아닙니다. 메일을 받을 수 없다면 IT 관리자가 본인 확인 후 관리자 초기화를 수행합니다. 메일 주소를 모르는 상태에서 다른 주소를 지정해 재설정할 수는 없습니다.

복구 링크 메일은 VPN/NAS 알림 작업자가 발송합니다. 기존 VPN 작업자를 실행 중이면 다음 주기에 처리됩니다. VPN 그룹 반영 없이 알림만 처리하려면:

```powershell
.\.venv\Scripts\python.exe manage.py process_directory_access --mail-only --watch --interval 60
```

0007 migration을 적용해야 합니다. 토큰은 DB에 해시로 저장하고 메일 전송 전용 값은 암호화합니다. 발송 후 대기열에서 전송용 암호문을 지웁니다. URL fragment(`#`)로 전달한 토큰은 서버 접근 로그로 전송되지 않으며 페이지가 로드되면 주소 표시줄에서 제거합니다. 재설정 제출 시에만 HTTPS POST 본문으로 전달합니다. 새 요청은 이전 링크를 무효화하고, 만료·사용 완료·이메일/LDAP ID/웹 인증 해시 변경 후에는 사용할 수 없습니다. 실제 NAS 변경을 시도한 링크는 실패해도 소비되어 다시 요청해야 합니다. 현재 환경에서는 실제 메일 서버/NAS 복구 성공 여부를 별도 확인해야 합니다.

복구 요청 응답은 계정 존재 여부와 무관하게 동일하고 CSRF 검증 및 요청 제한을 적용합니다. 이 메일은 재설정 권한을 포함하므로 다른 사람에게 전달하지 않도록 안내합니다. 등록된 회사 이메일에 접근할 수 없는 경우 관리자 확인 절차가 필요합니다.
