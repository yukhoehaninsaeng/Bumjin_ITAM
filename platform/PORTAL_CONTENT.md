# 직원 포털 공지·자주 찾는 도움말

## 사용 방법

관리자 설정 → **공지·도움말**에서 글을 작성합니다. GLOBAL system_admin만 작성/수정/게시할 수 있습니다.

1. 공지 작성 또는 도움말 작성 클릭. 새 글은 초안으로 생성됩니다.
2. 제목·본문, 공개 대상(전체 직원/선택 법인)을 입력합니다.
3. 이미지는 파일 선택, 끌어 놓기, 본문에 스크린샷 붙여넣기로 추가합니다.
4. 이미지 설명을 입력하거나 위로/아래로 버튼으로 순서를 바꿀 수 있습니다. 이미지는 본문 아래에 표시됩니다.
5. 미리보기로 확인한 뒤 상태를 **게시**로 선택하고 저장합니다. 초안/보관 상태는 직원에게 보이지 않습니다.

게시글을 잠시 내리려면 보관을 선택합니다. 수정 화면에서 상태를 게시로 바꾸면 다시 공개할 수 있습니다. 상단 고정 여부와 표시 순서(작은 값 우선)를 지정할 수 있습니다. ‘자주 찾는 도움말’은 관리자가 선정한 도움말 목록이며 검색량을 집계한 인기 순위는 아닙니다.

직원 `/portal` 홈에는 공지 최대 5개·도움말 최대 6개를 표시하고 전체 보기에서 종류별 검색·페이지 이동이 가능합니다. 직원은 자신의 법인과 전체 직원용 게시글만 볼 수 있습니다. `/portal/knowledge?article=게시글UUID`에서 상세 내용을 읽습니다. 퇴사/비활성 직원과 로그인하지 않은 사용자는 글/이미지에 접근할 수 없습니다.

## 이미지

- PNG/JPG/WEBP, 원본 파일당 최대 5MB·2천만 화소, 게시글당 최대 5장.
- 실제 이미지 형식을 검증하고 긴 변 최대 1600px의 WEBP로 다시 저장합니다. 원본 메타데이터와 실행 가능한 HTML/SVG를 게시하지 않습니다. 애니메이션은 첫 프레임 이미지로 처리됩니다.
- 초안에서 업로드한 이미지는 관리자에게만 보입니다. 글을 저장해야 첨부가 반영됩니다. 다른 글의 이미지를 ID로 지정해 첨부할 수 없습니다.
- 본문은 일반 텍스트와 줄바꿈으로 표시합니다. 입력한 HTML/스크립트는 실행하지 않습니다. 이미지가 들어간 글은 미리보기와 직원 상세 화면에서 동일한 순서로 표시됩니다.
- 이미지 파일은 기존 MEDIA_ROOT(기본 platform/private-files) 아래 portal-articles 폴더에 저장합니다. DB에는 파일 경로와 설명·순서를 저장합니다. NAS 폴더를 익명 웹 경로로 직접 공개하지 마세요. 인증 API가 글의 현재 공개 범위를 검사하고 이미지를 제공합니다.
- 수정·저장 시 제외한 이미지 파일은 트랜잭션 성공 후 정리합니다. 취소한 편집 중 올린 미사용 이미지는 정리 명령으로 24시간 후 삭제할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe manage.py cleanup_board_images
```

필요하면 NAS 스케줄러에서 하루 1회 실행합니다. 보관된 글의 첨부 이미지는 복원을 위해 유지합니다. DB 서버와 NAS를 분리한 경우 **DB 백업과 NAS의 MEDIA_ROOT 이미지 폴더를 함께 백업**해야 합니다.

## 코드 적용

이 변경은 VPN·NAS 기능 PR #12 이후 migration을 사용합니다. 기존 로컬 config/settings.py와 .settings.key는 유지합니다.

```powershell
cd 'C:\Users\BJE\Desktop\AI_PJT\Bumjin_ITAM-main\platform'
$env:ITAM_DEBUG = '1'
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

운영 서버는 기존 배포 방식대로 정적 파일을 수집하고 웹 프로세스를 재시작합니다. 이미지 저장 경로의 쓰기 권한과 영구 볼륨을 유지합니다. 새 migration 0008은 게시글/이미지 테이블과 PostgreSQL RLS를 추가합니다. 서버 DB 역할은 테이블 소유자 또는 BYPASSRLS여야 하며 Supabase 브라우저용 공개 정책을 추가하지 않습니다.

초기 샘플 글은 자동 게시하지 않습니다. 관리자 설정에서 공지·도움말을 직접 등록하세요. 글 작성/수정/게시/보관/이미지 업로드 이력은 기존 AuditEvent와 관리자 설정 변경 이력에서 확인할 수 있습니다. 다른 관리자의 수정과 버전이 충돌하면 다시 열어야 합니다.

## 확인 범위

임시 SQLite/임시 파일 저장소로 초안/게시/보관, 법인별 접근, 이미지 검증·최적화·순서·권한·정리, 버전 충돌을 검증합니다. 실제 운영 NAS의 이미지 저장 권한·백업, PostgreSQL 동시 수정, 실제 모바일 브라우저 화면은 배포 환경에서 확인해야 합니다.
