# Bumjin ITAM

범진의 기존 **Bumjin_IT자산관리대장.xlsx** 양식을 활용하는 웹 기반 IT 자산관리 프로그램입니다. PC·모니터·소프트웨어 기재 정보·전산 유지보수 계약을 관리합니다.

현재 권장 실행 방식은 **Windows PC 또는 사내 서버에서 Python 앱 실행**입니다. 별도 DB 서버 없이 로컬 Excel 파일에 저장합니다.

## 프로그램 구성과 사용 순서

Python 서버가 Excel을 읽고 저장하며, 관리자는 브라우저로 접속합니다. 서버를 종료하면 웹 접속도 중지됩니다. 로컬 실행에는 Node.js나 별도 DB 서버가 필요하지 않습니다.

1. 소스를 다운로드하고 테스트 Excel 준비
2. Python 서버 실행
3. 관리자 로그인
4. 자산 목록·QR·유지보수 메뉴 사용
5. 변경 사항 저장 및 백업 확인

| 구분 | 기능 |

| 대시보드 | 사업부별 장비, 사용 상태, OFFICE 버전, 소프트웨어 기재 현황 |
| 점검 목록 | 사용 중 사용자 미배정, 일련번호·날짜 누락, 5년 이상 장비 |

## 빠른 실행 — Windows

### 1. 다운로드 및 Python 확인

[저장소](https://github.com/yukhoehaninsaeng/Bumjin_ITAM)에서 **Code → Download ZIP**으로 다운로드하고 압축을 푸세요. 아래 명령의 `C:\ITAM`은 예시 경로이므로 실제 압축을 푼 폴더에 맞춰 바꿉니다.

PowerShell에서 확인:

```powershell
py --version
```

### 2. 테스트 Excel 준비

- Python 3.11 이상
- 이 저장소를 다운로드하거나 clone
- 테스트 Excel을 아래 경로에 배치

```text
Bumjin_ITAM/
├─ public/
│  └─ index.html
└─ backend/
   ├─ app.py
   ├─ start.ps1
   └─ data/
      └─ Bumjin_IT자산관리대장.xlsx
```

Excel 파일은 공개 저장소에 포함되지 않습니다. 내려받은 파일 이름에 붙은 `(1)` 등을 제거하세요.

### 3. 내 PC에서 실행

PowerShell에서 프로젝트의 backend 폴더로 이동합니다.

```powershell
cd C:\ITAM\backend
$env:HOST = '127.0.0.1'
$env:PORT = '1880'
$env:PUBLIC_BASE_URL = 'http://127.0.0.1:1880'
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

최초 실행 시 가상 환경과 패키지를 설치하고, **12자 이상 테스트 관리자 비밀번호**를 입력받습니다.

- 접속: http://127.0.0.1:1880
- 사용자 이름: `admin`
- 비밀번호: 실행 때 입력한 값
- 종료: PowerShell에서 **Ctrl+C**
- 실행 중 PowerShell 창을 유지하세요.

### 4. 휴대폰 및 다른 PC에서 접속

기존 서버를 Ctrl+C로 종료한 뒤 설정을 바꾸고 재실행합니다. `YOUR_PC_IP`는 실제 실행 PC의 IPv4 주소로 교체해야 하는 자리표시자입니다. PowerShell에서 `ipconfig`로 확인하세요.

```powershell
$env:HOST = '0.0.0.0'
$env:PUBLIC_BASE_URL = 'http://YOUR_PC_IP:1880'
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

브라우저 주소: `http://YOUR_PC_IP:1880` — 자리표시자를 실제 PC 주소로 바꿔 입력

휴대폰에서 해당 PC에 접근 가능한 사내 Wi-Fi를 사용하고, 필요한 경우 Windows 방화벽의 TCP 1880 접근을 허용합니다. HTTP에서는 테스트 비밀번호를 사용하고 실제 운영은 HTTPS를 구성하세요.

환경변수 변경 후 서버를 재시작해야 새 QR 주소에 반영됩니다. 기존에 인쇄한 QR은 이전 주소를 포함할 수 있습니다.

## 자산 관리

### 자동 관리번호

| 법인 | 데스크톱 | 노트북 | 모니터 |
|---|---|---|---|
| BJM | BJM-D-001 | BJM-N-001 | BJM-M-001 |
| BJE | BJE-D-001 | BJE-N-001 | BJE-M-001 |
| BJC | BJC-D-001 | BJC-N-001 | BJC-M-001 |

신규 등록 시 **같은 접두어의 최대 번호 + 1**로 생성합니다. 기존 `MD001`, `CN001`, `MM001` 등의 코드는 유지하며, 이 레거시 번호는 새 형식의 번호 계산에 합산하지 않습니다. 최대 번호 아래의 빈 번호를 채우지 않습니다. 별도 번호 예약 대장이 없으므로 최고 번호 행을 직접 삭제하는 운영은 피하세요.

다른 사용자가 먼저 저장해 Excel 버전이 바뀌면 새로고침 후 다시 등록해야 합니다.

### QR와 사용자 변경

1. 자산 목록에서 장비 선택
2. QR 인쇄로 라벨 생성
3. 휴대폰에서 QR 촬영 → 관리자 로그인 → 해당 자산 상세
4. 현재 사용자 확인, 사용자 변경 또는 수거·반납 처리

인쇄 라벨에는 **QR 코드·자산관리 코드·Bumjin 로고**가 표시됩니다. 브라우저 인쇄 설정의 머리글·바닥글을 끄면 날짜·URL이 제외됩니다.

- **사용자 확인:** 현재 배정 정보 확인 이력을 저장
- **사용자 변경:** 새 이름 또는 가져온 LDAP 계정을 선택하고 사용 상태로 저장
- **수거 / 반납:** 사용자 및 LDAP 배정을 해제하고 보관 상태로 저장
- 기존 사용자 정보는 변경 이력에 남습니다.

현재는 공용 관리자 로그인이므로 QR을 촬영한 직원의 신원을 자동으로 식별하지 않습니다.

### 소프트웨어 및 날짜

- 공통 PC: OS·에디션·OFFICE·한글
- BJM: OfficeKeeper·V3
- BJE·BJC: SAP·백신·Docuone·기타
- 모니터: 제조일자
- BJM PC: 구매일자 / BJE PC: 구입년월 / BJC PC: 제조일자

소프트웨어 현황은 **Excel 기재값 기준**입니다. 실제 설치 여부·사용 시간·정품 라이선스 보유를 자동 검증하지 않습니다. 제조일을 구매일로 간주하지 않습니다.

## 폼텍 QRP-3990 일괄 라벨 출력

1. 자산 목록의 체크박스로 자산 선택
2. **QRP-3990 PDF 인쇄** 클릭
3. 28칸 미리보기에서 시작 칸 선택
4. 필요 시 좌우·상하 보정과 용지 여백·칸 간격 설정
5. A4 PDF 다운로드 후 **실제 크기 100%**로 인쇄

- 4열 × 7행, 라벨 40×40mm, 라벨 내용 95% 크기
- 시작 칸 앞은 비워두고 다음 페이지는 1번 칸부터 자동 배치
- 검색 결과 전체 선택 및 선택 해제, 페이지 간 선택 유지
- 한 번에 최대 500개
- 기본 프로필: 왼쪽 20.5mm / 위쪽 7mm / 가로 피치 43mm / 세로 피치 40mm
- 상세 배치는 일반 A4에 시험 출력해 실제 라벨지와 겹쳐 확인하세요. 필요한 값은 출력 창에서 변경할 수 있습니다.
- 양수 보정은 오른쪽·아래 이동, 음수는 왼쪽·위 이동
- 시험 출력용 테두리 옵션은 실제 라벨 출력 전 끄세요.
- PDF의 페이지 크기와 칸 위치는 A4 기준입니다. 프린터의 페이지 맞춤·축소 기능은 끄세요.
- 로컬 Python 서버에서 지원합니다. Vercel 브리지에 신규 PDF API는 연결되지 않았습니다.

업데이트 파일: `backend/app.py`, 새 `backend/label_pdf.py`, `public/index.html`. 로고 파일 `public/qr-label-logo.svg`도 유지하세요.

## 전산 유지보수

왼쪽 메뉴의 **전산 유지보수**에서 계약을 조회합니다.

- 업체·서비스·사업부 검색
- 계약 시작·만료일, 오늘 기준 남은 일수
- 30일 내 만료 및 만료된 계약 수
- 2024·2025·2026 입력 비용 및 2026 합계
- 담당자·수량·비고·비용·갱신일 수정
- 신규 계약 등록

원본 계약은 `2.전산 유지보수` 시트의 계약 영역을 수정합니다. 병합 셀의 공유 정보는 그룹 대표 행에서 수정해야 합니다. 신규 계약은 원본 병합 서식을 유지하기 위해 **앱_유지보수** 시트에 저장합니다.

AutoCAD 등 같은 시트의 추가 대장은 **조회만 지원**합니다. 비용은 원본에 입력된 값의 합계이며 세금·통화·회계 처리 기준을 자동 판정하지 않습니다.

## Excel 저장 및 운영

| 위치 | 저장 내용 |
|---|---|
| 원본 PC·모니터 시트 | 자산 정보 및 사용자 |
| 숨김 AZ열 | QR용 자산 UUID |
| 숨김 BA열 | LDAP uid |
| 앱_이력 | 등록·변경·확인·수거·유지보수 수정 이력 |
| 앱_LDAP사용자 | 가져온 LDAP 사용자 |
| 앱_유지보수 | 신규 유지보수 계약 |
| data/backups | 저장 전 Excel 백업 |

- 앱 실행 중 같은 Excel을 직접 편집하지 마세요.
- 파일은 로컬 디스크에 두고 **한 서버·한 프로세스**에서 작성하세요.
- Google Drive 동기화 폴더나 SMB 공유 파일의 다중 작성은 지원하지 않습니다.
- 앱 초기 실행 시 백업 후 UUID와 관리 시트를 추가합니다.
- 숨김 열과 앱 시트를 삭제하지 마세요. 원본 파일로 다시 교체하면 기존 QR 연결이 달라질 수 있습니다.
- 복구는 서버 종료 후 백업 XLSX를 운영 파일 위치로 복사합니다.
- Excel 수식은 보존하되 Python 앱이 Excel 계산 엔진처럼 모든 수식을 재계산하지는 않습니다.

Google Drive 자동 업로드는 **미구현**입니다. 현재 저장 대상은 PC/사내 서버의 XLSX이며 Drive 반영은 수동입니다.

## 관리자 설정과 사용자 리스트

- `/admin`: 현재 비밀번호 확인 후 관리자 비밀번호 변경, LDAPS 연결 설정 저장, 사용자·OU 가져오기
- `/users`: LDAP 조직·부서 필터, 사용자 검색, 사용자별 PC·모니터·기재 소프트웨어, 개별 자산 수거
- 비밀번호는 PBKDF2 해시로 `backend/data/admin_settings.json`에 저장합니다. 설정 파일은 Git에서 제외합니다.
- LDAP Bind 비밀번호는 실행 중 메모리에만 유지합니다. 재시작 후 다시 입력하거나 서버의 `LDAP_BIND_PASSWORD` 환경변수를 사용하세요.
- LDAPS 인증서 검증은 기본 사용이며, 관리자 화면에서 사설 CA 경로 또는 테스트용 검증 생략을 설정합니다.
- 조직은 앱에서 생성하거나 LDAP 부서 경로로 구성합니다. 사용자 배정 시 LDAP 부서 속성에 반영하며 LDAP OU를 생성하거나 이동하지 않습니다.
- 사용자 자산은 UID 매핑 기준입니다. 기존 이름 기반 자산은 별도로 표시하며 LDAP 계정을 선택해 매핑해야 합니다.
- 사용자 목록 가져오기는 자산 배정을 자동 변경하거나 계정을 생성·삭제하지 않습니다.
- 비밀번호 변경 후 새 비밀번호로 다시 로그인하세요. 전체 페이지는 현재 공용 관리자 권한으로 보호됩니다.
- 로컬 Python 앱에서 지원합니다. Vercel 브리지에는 관리자·사용자 화면과 신규 API 경로의 추가 연결이 필요합니다.
- 업데이트 시 `app.py`, `admin_service.py`, `start.ps1`, `public/index.html`을 함께 교체하세요.

## LDAP

`backend/sync_ldap.py`로 사용자 목록을 가져옵니다. 상세 설정은 [backend/README.md](backend/README.md)를 참고하세요.

- 사내 LDAP에 접근 가능한 네트워크 필요
- LDAPS 사용. 운영 환경은 CA 인증서와 호스트 이름 검증 권장
- 조회만 할 때는 읽기 전용 계정, 부서 수정 시에는 부서 속성에 쓰기 권한이 있는 서비스 계정 사용
- 실명·안정적 식별자 속성과 직원 검색 필터를 현장에서 확인
- 웹앱을 종료한 뒤 가져오기 실행

환경변수 예제 파일은 자동 로드되지 않습니다. PowerShell 또는 서비스 환경에 실제 값을 설정하세요. LDAP 개인 로그인·정기 자동 동기화·기존 이름의 자동 대량 매핑은 아직 없습니다.

## Vercel 구성과 현재 상태

저장소에는 정적 화면과 사내 API 연결용 브리지가 포함돼 있습니다.

- Framework: Other
- Root Directory: 저장소 루트
- Install: `npm install --ignore-scripts`
- Build: `npm run build`
- 빌드 결과: `.vercel/output` — `vercel.json`에서 지정
- 연결 변수: `BACKEND_URL`, `BACKEND_GATEWAY_TOKEN`
- Python 서버에도 같은 게이트웨이 토큰 및 공개 웹 주소 설정 필요

**실제 Vercel 배포는 아직 성공 확인되지 않았습니다.** 반복된 출력 디렉터리 오류 이후 현재는 로컬 실행을 기준으로 개발·시험하고 있습니다. 기존 브리지는 자산 API·QR·Excel 다운로드 경로를 지원하지만, **신규 유지보수 API 경로는 아직 연결되지 않았습니다.** 전체 기능 사용은 로컬 Python 앱으로 진행하세요.

Vercel에서 사내 API를 사용하려면 접근 가능한 HTTPS 경로가 필요합니다. 사내 IP 또는 `.local` 주소만 입력해서는 사내망 연결이 만들어지지 않습니다.

## LDAP 사용자 표시와 조직 관리

사용자 카드에는 **계정명 → NAS 설명 → 이메일**을 표시합니다. 관리자 설정의 설명 속성 기본값은 `description`입니다. 기존 목록은 LDAP를 다시 동기화해야 설명이 채워집니다. 자산 배정에 사용하는 표시이름 속성은 별도로 유지됩니다.

1. NAS에서 테스트 사용자 한 명의 설명과 부서를 입력합니다.
2. 앱 관리자에서 LDAPS 주소, Bind DN, 비밀번호를 저장하고 사용자를 동기화합니다. 연결 버튼은 화면의 설정을 먼저 저장합니다.
3. 사용자 리스트에서 한 명을 선택하고 **선택 1명 LDAP 속성 확인**을 누릅니다. 반환된 값으로 실제 설명·부서 속성을 확인합니다. 비밀번호 등의 속성은 반환하지 않습니다.
4. 관리자에서 부서 속성을 지정합니다. 쓰기는 `departmentNumber`, `department`, `ou` 중 실제 서버에서 확인한 속성만 허용하며, **LDAP 부서 수정**을 활성화해야 합니다. 연결 계정에는 해당 사용자 부서 속성 수정 권한이 필요합니다.
5. 사용자 리스트의 **법인·부서 추가**에서 법인 → 본부 → 팀을 생성합니다.
6. 사용자 1~50명을 선택하고 배정할 조직을 선택하거나 조직에 끌어 놓습니다. 변경 미리보기를 확인하고 **LDAP에 부서 저장**을 누릅니다.
7. NAS 화면에서 테스트 계정의 부서가 반영됐는지 확인한 다음 범위를 넓힙니다.

조직 정의는 Excel의 `앱_조직`에 저장합니다. 사용자 배정 시에만 LDAP 부서 값이 `법인/본부/팀` 형태로 수정됩니다. LDAP OU 생성·DN 이동·계정 생성·비밀번호 변경 기능이 아닙니다. 빈 조직과 상하위 정의는 다른 LDAP 시스템으로 전송되지 않으며 다른 시스템이 경로를 트리로 해석하려면 그 시스템도 경로 매핑을 지원해야 합니다.

- LDAP 동기화 시 부서 경로로 조직을 복원하며, 앱에서 만든 빈 조직도 유지합니다.
- 이미 사용자가 소속된 조직은 이름/상위를 바로 바꾸거나 삭제할 수 없습니다. 새 조직을 만들고 사용자를 배정한 뒤 빈 조직을 정리합니다.
- 미배정으로 배정하면 해당 사용자의 LDAP 부서 속성을 비웁니다. 사용자 계정이나 지급 자산은 삭제하지 않습니다.
- 계정 확인은 디렉터리 고유 ID로 하며 수정 전 LDAP의 계정·부서를 재조회합니다. 외부 변경 감지 시 동기화를 요구합니다.
- 여러 LDAP 사용자 변경은 하나의 트랜잭션이 아닙니다. 중간 실패 시 중단하고 성공·실패·미처리 수를 표시합니다. 성공한 사용자를 자동으로 되돌리거나 재시도하지 않습니다. 다른 관리 도구와 동시에 같은 사용자 부서를 수정하지 마세요.
- 변경 결과는 `앱_조직변경이력` 및 데이터 폴더의 `ldap_department_audit.jsonl`에 남습니다. 네트워크 단절이나 Excel 저장 실패 시 LDAP를 다시 동기화하고 감사 기록을 확인합니다.
- Bind 비밀번호는 메모리에만 유지됩니다. 컨테이너 재시작 후 다시 입력하거나 NAS의 비공개 런타임 환경변수 `LDAP_BIND_PASSWORD`를 사용합니다.
- 인증서 검증은 기본 사용입니다. 사내 테스트에서 관리자가 생략을 명시적으로 선택할 수 있습니다. 이때도 LDAPS 암호화는 유지되지만 서버 신원 확인은 생략됩니다. CA 경로는 검증 사용 시에만 적용합니다.

### NAS 업데이트

`backend/admin_service.py`, `backend/organization_service.py`, `backend/app.py`, `public/index.html`을 함께 갱신한 뒤 Docker 이미지를 다시 빌드하고 기존과 같은 데이터·환경설정·인증서 마운트로 컨테이너를 재생성합니다. **컨테이너 재시작만으로 이미지 안의 코드가 갱신되지는 않습니다.** 기존 Excel을 교체하거나 삭제하지 마세요. 새 관리 시트는 작업 시 자동으로 생성됩니다.

개발 검증: 실제 업무 Excel의 사본을 사용해 `TEST_WORKBOOK=/absolute/path/test.xlsx ASSET_FILE=/absolute/path/test.xlsx python -m unittest discover -s backend`를 실행합니다. 자동 테스트는 LDAP 모의 연결을 사용하므로 NAS의 실제 스키마·ACL·인증서 및 쓰기 반영은 테스트 계정으로 추가 확인해야 합니다.


## 이름 기반 자산의 LDAP 일괄 매핑

사용자 리스트에서 **LDAP 미매핑 · 이름 기반** 사용자를 클릭하면 상세 상단에 LDAP 계정 검색·선택과 자산 선택 기능이 나타납니다.

1. 연결할 LDAP 계정을 계정명·설명·이메일로 검색하고 선택합니다.
2. 현재 이름으로 배정된 PC·모니터 중 대상 자산을 선택합니다. 기본은 전체 선택이며 동명이인·공용 장비는 제외하세요.
3. **선택 자산 매핑 미리보기**에서 관리번호·법인·부서를 확인합니다.
4. **선택 자산 일괄 매핑**을 누르면 최대 500개 자산의 LDAP uid와 사용자 표시이름을 Excel에 한 번에 저장합니다.
5. 매핑 후에는 선택한 LDAP 사용자 상세에서 기존 자산과 새로 매핑한 자산을 함께 조회합니다. 일부만 매핑하면 나머지는 이름 기반 목록에 남습니다.

자산 상태·부서·사양·SW 기재값은 유지합니다. PC의 SW 정보는 해당 PC와 함께 사용자 상세에서 조회되며 별도 라이선스 지급 내역을 새로 만들지는 않습니다. NAS LDAP의 사용자·비밀번호·부서를 수정하는 작업이 아니라 **자산대장에 LDAP 계정을 연결**하는 작업입니다. 기존 매핑이 있거나 사용자/Excel이 변경된 경우 전체 저장을 중단합니다. 자산별 이력에 `LDAP 일괄 매핑`이 남습니다.

NAS에는 `backend/app.py`와 `public/index.html`을 함께 업데이트하고 이미지를 재빌드한 뒤 컨테이너를 재생성해야 합니다. 앞선 조직 관리 버전의 `backend/admin_service.py`, `backend/organization_service.py`도 있어야 합니다.


## Excel 사업부·부서로 초기 조직도 구성

최초 업데이트 실행 시 PC·모니터 대장의 사업부(BJC/BJE/BJM)와 부서로 조직도를 구성합니다. 같은 부서명도 사업부가 다르면 별도 조직입니다. 공백으로 상하위를 추측하지 않으며, 예를 들어 `연구소 회로개발팀`은 한 부서로 유지합니다. 명시적인 `/` 경로는 계층으로 읽습니다.

- **사용자 리스트 → 조직도 → 편집**에서 이름·상위 조직을 수정하고 법인·본부·팀을 추가할 수 있습니다.
- 조직을 클릭하면 LDAP 사용자뿐 아니라 해당 조직의 이름 기반 자산 사용자도 조회합니다. 조직별 사용자 수와 연결 자산 수를 표시합니다.
- 정의는 `앱_조직`, 자산의 조직 연결은 `앱_자산조직`, 최초 가져오기 상태는 `앱_조직가져오기`에 저장합니다. 조직을 수정해도 자산 연결 ID를 유지합니다.
- 최초 가져오기는 한 번만 실행하므로 재시작 때 수정 전 부서가 다시 생기지 않습니다. 기존에 앱에서 만든 조직도 유지합니다.
- 조직도 편집은 원본 자산대장의 사업부·부서 셀과 NAS LDAP 속성을 자동 변경하지 않습니다. LDAP 사용자 소속 변경은 기존의 배정 미리보기·확인 절차로 별도 적용합니다.
- 자산이나 하위 조직이 있는 조직은 바로 삭제하지 못합니다. LDAP 소속 사용자가 있는 조직의 경로 변경 제한도 유지됩니다.
- 최초 가져오기 이후 Excel에서 외부로 새로 입력한 부서는 자동으로 다시 가져오지 않습니다. 이후 조직은 앱에서 관리합니다.
- 자산 현황의 로컬 테스트·Drive 미연결 안내 문구는 제거했습니다. 오류 발생 시에는 오류 메시지만 표시합니다.

NAS 적용 파일: `backend/organization_service.py`, `backend/app.py`, `public/index.html`. 기존 데이터 폴더와 Excel을 유지한 채 파일을 갱신하고 Docker 이미지를 재빌드한 뒤 컨테이너를 재생성합니다. 브라우저는 강력 새로고침으로 갱신하세요.


## 회사 로고 로그인 페이지와 세션 인증

`/login`에서 회사 로고, 아이디·비밀번호 입력창, 빨간 로그인 버튼을 제공합니다. 브라우저의 HTTP Basic 팝업 인증을 제거했으며 기존 관리자 계정 `admin`과 현재 관리자 비밀번호를 그대로 사용합니다. 회원가입·게스트 접근·LDAP 개인 로그인 기능은 포함하지 않습니다.

- 인증 전 자산 현황·관리자·사용자·QR 주소로 접근하면 로그인 페이지로 이동합니다. 로그인 후에는 원래 QR 자산 또는 요청했던 페이지로 돌아갑니다.
- 인증되지 않은 API는 `401` JSON을 반환하며 `WWW-Authenticate` 헤더를 보내지 않습니다.
- 세션은 서버 메모리에 8시간 유지하며, 브라우저에는 HttpOnly·SameSite=Lax 쿠키만 저장합니다. 비밀번호를 브라우저 저장소에 저장하지 않습니다.
- HTTPS 직접 접속 또는 HTTPS `PUBLIC_BASE_URL` 설정 시 Secure 쿠키를 사용합니다. 설정 주소의 프로토콜을 실제 접속 주소와 일치시키세요.
- 메뉴 하단의 **로그아웃**으로 현재 세션을 종료합니다. 관리자 비밀번호 변경 시 기존 세션은 무효화됩니다. 서버 재시작 시에도 다시 로그인합니다.
- 로그인 전용 CSRF 토큰과 로그인 세션별 CSRF 토큰을 분리합니다. 로그인 실패가 같은 접속 주소에서 5분 내 8회 누적되면 일시 제한합니다.
- 기존 Basic Authorization 헤더만으로 API에 접근하는 방식은 더 이상 지원하지 않습니다. 브라우저는 로그인 폼을 사용합니다.
