# Bumjin ITAM

범진의 기존 **Bumjin_IT자산관리대장.xlsx** 양식을 활용하는 웹 기반 IT 자산관리 프로그램입니다. PC·모니터·소프트웨어 기재 정보·전산 유지보수 계약을 관리합니다.

현재 권장 실행 방식은 **Windows PC 또는 사내 서버에서 Python 앱 실행**입니다. 별도 DB 서버 없이 로컬 Excel 파일에 저장합니다.

## 프로그램 구성과 사용 순서

Python 서버가 Excel을 읽고 저장하며, 관리자는 브라우저로 접속합니다. 서버를 종료하면 웹 접속도 중지됩니다. 로컬 실행에는 Node.js나 별도 DB 서버가 필요하지 않습니다.

1. 소스를 다운로드하고 테스트 Excel 준비
2. Python 서버 실행
3. 관리자 로그인
4. 자산 목록·QR·유지보수 메뉴 사용
5. 변경 사항 저장 및 백업 확인

## 빠른 실행 — Windows

### 1. 다운로드 및 Python 확인

[저장소](https://github.com/yukhoehaninsaeng/Bumjin_ITAM)에서 **Code → Download ZIP**으로 다운로드하고 압축을 푸세요. 아래 명령의 `C:\ITAM`은 예시 경로이므로 실제 압축을 푼 폴더에 맞춰 바꿉니다.

PowerShell에서 확인:

```powershell
py --version
```

### 2. 테스트 Excel 준비

- Python 3.11 이상
- 이 저장소를 다운로드하거나 clone
- 테스트 Excel을 아래 경로에 배치

```text
Bumjin_ITAM/
├─ public/
│  └─ index.html
└─ backend/
   ├─ app.py
   ├─ start.ps1
   └─ data/
      └─ Bumjin_IT자산관리대장.xlsx
```

Excel 파일은 공개 저장소에 포함되지 않습니다. 내려받은 파일 이름에 붙은 `(1)` 등을 제거하세요.

### 3. 내 PC에서 실행

PowerShell에서 프로젝트의 backend 폴더로 이동합니다.

```powershell
cd C:\ITAM\backend
$env:HOST = '127.0.0.1'
$env:PORT = '1880'
$env:PUBLIC_BASE_URL = 'http://127.0.0.1:1880'
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

최초 실행 시 가상 환경과 패키지를 설치하고, **12자 이상 테스트 관리자 비밀번호**를 입력받습니다.

- 접속: http://127.0.0.1:1880
- 사용자 이름: `admin`
- 비밀번호: 실행 때 입력한 값
- 종료: PowerShell에서 **Ctrl+C**
- 실행 중 PowerShell 창을 유지하세요.

### 4. 휴대폰 및 다른 PC에서 접속

기존 서버를 Ctrl+C로 종료한 뒤 설정을 바꾸고 재실행합니다. `YOUR_PC_IP`는 실제 실행 PC의 IPv4 주소로 교체해야 하는 자리표시자입니다. PowerShell에서 `ipconfig`로 확인하세요.

```powershell
$env:HOST = '0.0.0.0'
$env:PUBLIC_BASE_URL = 'http://YOUR_PC_IP:1880'
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

브라우저 주소: `http://YOUR_PC_IP:1880` — 자리표시자를 실제 PC 주소로 바꿔 입력

휴대폰에서 해당 PC에 접근 가능한 사내 Wi-Fi를 사용하고, 필요한 경우 Windows 방화벽의 TCP 1880 접근을 허용합니다. HTTP에서는 테스트 비밀번호를 사용하고 실제 운영은 HTTPS를 구성하세요.

환경변수 변경 후 서버를 재시작해야 새 QR 주소에 반영됩니다. 기존에 인쇄한 QR은 이전 주소를 포함할 수 있습니다.

## 자산 관리

### 자동 관리번호

| 법인 | 데스크톱 | 노트북 | 모니터 |
|---|---|---|---|
| BJM | BJM-D-001 | BJM-N-001 | BJM-M-001 |
| BJE | BJE-D-001 | BJE-N-001 | BJE-M-001 |
| BJC | BJC-D-001 | BJC-N-001 | BJC-M-001 |

신규 등록 시 **같은 접두어의 최대 번호 + 1**로 생성합니다. 기존 `MD001`, `CN001`, `MM001` 등의 코드는 유지하며, 이 레거시 번호는 새 형식의 번호 계산에 합산하지 않습니다. 최대 번호 아래의 빈 번호를 채우지 않습니다. 별도 번호 예약 대장이 없으므로 최고 번호 행을 직접 삭제하는 운영은 피하세요.

다른 사용자가 먼저 저장해 Excel 버전이 바뀌면 새로고침 후 다시 등록해야 합니다.

### QR와 사용자 변경

1. 자산 목록에서 장비 선택
2. QR 인쇄로 라벨 생성
3. 휴대폰에서 QR 촬영 → 관리자 로그인 → 해당 자산 상세
4. 현재 사용자 확인, 사용자 변경 또는 수거·반납 처리

인쇄 라벨에는 **QR 코드·자산관리 코드·Bumjin 로고**가 표시됩니다. 브라우저 인쇄 설정의 머리글·바닥글을 끄면 날짜·URL이 제외됩니다.

- **사용자 확인:** 현재 배정 정보 확인 이력을 저장
- **사용자 변경:** 새 이름 또는 가져온 LDAP 계정을 선택하고 사용 상태로 저장
- **수거 / 반납:** 사용자 및 LDAP 배정을 해제하고 보관 상태로 저장
- 기존 사용자 정보는 변경 이력에 남습니다.

현재는 공용 관리자 로그인이므로 QR을 촬영한 직원의 신원을 자동으로 식별하지 않습니다.

### 소프트웨어 및 날짜

- 공통 PC: OS·에디션·OFFICE·한글
- BJM: OfficeKeeper·V3
- BJE·BJC: SAP·백신·Docuone·기타
- 모니터: 제조일자
- BJM PC: 구매일자 / BJE PC: 구입년월 / BJC PC: 제조일자

소프트웨어 현황은 **Excel 기재값 기준**입니다. 실제 설치 여부·사용 시간·정품 라이선스 보유를 자동 검증하지 않습니다. 제조일을 구매일로 간주하지 않습니다.

## 전산 유지보수

왼쪽 메뉴의 **전산 유지보수**에서 계약을 조회합니다.

- 업체·서비스·사업부 검색
- 계약 시작·만료일, 오늘 기준 남은 일수
- 30일 내 만료 및 만료된 계약 수
- 2024·2025·2026 입력 비용 및 2026 합계
- 담당자·수량·비고·비용·갱신일 수정
- 신규 계약 등록

원본 계약은 `2.전산 유지보수` 시트의 계약 영역을 수정합니다. 병합 셀의 공유 정보는 그룹 대표 행에서 수정해야 합니다. 신규 계약은 원본 병합 서식을 유지하기 위해 **앱_유지보수** 시트에 저장합니다.

AutoCAD 등 같은 시트의 추가 대장은 **조회만 지원**합니다. 비용은 원본에 입력된 값의 합계이며 세금·통화·회계 처리 기준을 자동 판정하지 않습니다.

## Excel 저장 및 운영

| 위치 | 저장 내용 |
|---|---|
| 원본 PC·모니터 시트 | 자산 정보 및 사용자 |
| 숨김 AZ열 | QR용 자산 UUID |
| 숨김 BA열 | LDAP uid |
| 앱_이력 | 등록·변경·확인·수거·유지보수 수정 이력 |
| 앱_LDAP사용자 | 가져온 LDAP 사용자 |
| 앱_유지보수 | 신규 유지보수 계약 |
| data/backups | 저장 전 Excel 백업 |

- 앱 실행 중 같은 Excel을 직접 편집하지 마세요.
- 파일은 로컬 디스크에 두고 **한 서버·한 프로세스**에서 작성하세요.
- Google Drive 동기화 폴더나 SMB 공유 파일의 다중 작성은 지원하지 않습니다.
- 앱 초기 실행 시 백업 후 UUID와 관리 시트를 추가합니다.
- 숨김 열과 앱 시트를 삭제하지 마세요. 원본 파일로 다시 교체하면 기존 QR 연결이 달라질 수 있습니다.
- 복구는 서버 종료 후 백업 XLSX를 운영 파일 위치로 복사합니다.
- Excel 수식은 보존하되 Python 앱이 Excel 계산 엔진처럼 모든 수식을 재계산하지는 않습니다.

Google Drive 자동 업로드는 **미구현**입니다. 현재 저장 대상은 PC/사내 서버의 XLSX이며 Drive 반영은 수동입니다.

## 관리자 설정과 사용자 리스트

- `/admin`: 현재 비밀번호 확인 후 관리자 비밀번호 변경, LDAPS 연결 설정 저장, 사용자·OU 가져오기
- `/users`: LDAP 조직·부서 필터, 사용자 검색, 사용자별 PC·모니터·기재 소프트웨어, 개별 자산 수거
- 비밀번호는 PBKDF2 해시로 `backend/data/admin_settings.json`에 저장합니다. 설정 파일은 Git에서 제외합니다.
- LDAP Bind 비밀번호는 실행 중 메모리에만 유지합니다. 재시작 후 다시 입력하거나 서버의 `LDAP_BIND_PASSWORD` 환경변수를 사용하세요.
- LDAPS 인증서를 검증합니다. 사설 CA 인증서는 서버 경로로 지정하며 검증을 끄는 옵션은 제공하지 않습니다.
- 조직 조회는 실제 OU와 지정한 부서 속성 기준입니다. NAS 디렉터리에 OU가 없다면 조직도가 자동 생성되지는 않습니다.
- 사용자 자산은 UID 매핑 기준입니다. 기존 이름 기반 자산은 별도로 표시하며 LDAP 계정을 선택해 매핑해야 합니다.
- 사용자 목록 가져오기는 자산 배정을 자동 변경하거나 계정을 생성·삭제하지 않습니다.
- 비밀번호 변경 후 새 비밀번호로 다시 로그인하세요. 전체 페이지는 현재 공용 관리자 권한으로 보호됩니다.
- 로컬 Python 앱에서 지원합니다. Vercel 브리지에는 관리자·사용자 화면과 신규 API 경로의 추가 연결이 필요합니다.
- 업데이트 시 `app.py`, `admin_service.py`, `start.ps1`, `public/index.html`을 함께 교체하세요.

## LDAP

`backend/sync_ldap.py`로 사용자 목록을 가져옵니다. 상세 설정은 [backend/README.md](backend/README.md)를 참고하세요.

- 사내 LDAP에 접근 가능한 네트워크 필요
- LDAPS 및 인증서 검증 필요
- 읽기 전용 서비스 계정 사용
- 실명·안정적 식별자 속성과 직원 검색 필터를 현장에서 확인
- 웹앱을 종료한 뒤 가져오기 실행

환경변수 예제 파일은 자동 로드되지 않습니다. PowerShell 또는 서비스 환경에 실제 값을 설정하세요. LDAP 개인 로그인·정기 자동 동기화·기존 이름의 자동 대량 매핑은 아직 없습니다.

## Vercel 구성과 현재 상태

저장소에는 정적 화면과 사내 API 연결용 브리지가 포함돼 있습니다.

- Framework: Other
- Root Directory: 저장소 루트
- Install: `npm install --ignore-scripts`
- Build: `npm run build`
- 빌드 결과: `.vercel/output` — `vercel.json`에서 지정
- 연결 변수: `BACKEND_URL`, `BACKEND_GATEWAY_TOKEN`
- Python 서버에도 같은 게이트웨이 토큰 및 공개 웹 주소 설정 필요

**실제 Vercel 배포는 아직 성공 확인되지 않았습니다.** 반복된 출력 디렉터리 오류 이후 현재는 로컬 실행을 기준으로 개발·시험하고 있습니다. 기존 브리지는 자산 API·QR·Excel 다운로드 경로를 지원하지만, **신규 유지보수 API 경로는 아직 연결되지 않았습니다.** 전체 기능 사용은 로컬 Python 앱으로 진행하세요.

Vercel에서 사내 API를 사용하려면 접근 가능한 HTTPS 경로가 필요합니다. 사내 IP 또는 `.local` 주소만 입력해서는 사내망 연결이 만들어지지 않습니다.

## 종료 및 다시 실행

- 서버 PowerShell에서 **Ctrl+C**로 종료합니다.
- 재실행할 때 backend 폴더에서 `start.ps1`을 실행합니다.
- 새 PowerShell을 열면 HOST·PORT·PUBLIC_BASE_URL을 다시 설정하세요.
- `.env.example`은 참고 파일이며 자동으로 로드하지 않습니다.
- 서버 안내에 localhost가 표시돼도 HOST를 설정했다면 해당 PC 주소로 접속할 수 있습니다.

## 업데이트 방법

서버를 종료하고 최신 파일을 덮어쓴 뒤 재실행합니다.

| 변경 | 교체 파일 |
|---|---|
| 화면·디자인 | public/index.html |
| 서버 기능·데이터 처리 | backend/app.py |
| 전체 업데이트 | 저장소 코드 업데이트, 기존 backend/data 유지 |

브라우저는 Ctrl+F5로 새로고침하세요. 프로그램은 `public/index.html`을 제공하며 CSS와 JavaScript가 이 HTML에 포함되어 있습니다.

## 문제 해결

| 증상 | 해결 방법 |
|---|---|
| Python 명령을 찾을 수 없음 | Python 및 Windows Launcher 설치 확인, PowerShell 다시 열기 |
| 경로를 찾을 수 없음 | 실제 압축을 푼 위치와 backend 폴더 확인 |
| Excel을 찾을 수 없음 | 지정 파일명과 data 폴더 확인, 파일명의 (1) 접미사 제거 |
| 패키지 누락 | backend에서 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` 실행 |
| 비밀번호 입력이 안 보임 | 숨김 입력이므로 정상. 12자 이상 입력 후 Enter |
| 휴대폰 접속 불가 | HOST, PC 주소, 네트워크 접근 경로, 방화벽 확인 |
| QR에서 자산을 못 찾음 | 앱용 Excel의 UUID 유지 여부 확인, 현재 대장에서 QR 다시 출력 |
| 모니터 정보가 없음 | app.py와 index.html을 함께 교체하고 서버 재시작 |
| 디자인이 그대로임 | 실행 프로젝트의 public/index.html 확인 후 Ctrl+F5 |
| 저장 권한 오류 | Excel에서 파일을 닫고 다시 시도 |
| 다른 변경 / 세션 변경 오류 | 새로고침 후 다시 입력 |
| 실행 중인 앱이 있다는 오류 | 기존 서버 종료. 비정상 종료 후 실행 프로세스가 없음을 확인한 경우에만 해당 .app.lock 파일 제거 |

백엔드 테스트에는 테스트 XLSX가 필요하고 임시 복사본을 사용합니다. 자산 저장·충돌·인증·사용자 변경·수거를 검증합니다. 추가 개발 과정에서는 모니터 조회·저장, 소프트웨어 보존, 자동 번호, 유지보수 계약 등록·수정·병합 유지도 별도 점검했습니다.

실제 모바일 화면, LDAP 연결, Vercel 배포는 각 환경에서 확인해야 합니다.
