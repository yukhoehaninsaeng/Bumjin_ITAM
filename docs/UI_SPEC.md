## 1. 목적과 적용 범위

기존 Bumjin_ITAM의 디자인을 유지하면서 IT 자산, 티켓, 조직·직원 업무를 통합한다. 관리자와 일반 직원은 서로 다른 경로와 화면 구조로 진입한다.

관리자 첫 화면은 자산 통계 중심 화면에서 **티켓·자산·조직의 처리할 업무를 보여주는 통합 운영 대시보드**로 변경한다. 기존 ITAM 화면은 자산 관리 메뉴에서 계속 제공한다.

이 문서는 수정된 웹 목업의 구조를 기준으로 개발에 필요한 표시 규칙, 입력 검증, 권한, 오류·빈 상태를 보완한다. 목업은 샘플 데이터와 브라우저 내 임시 동작을 사용한다. 이 문서가 인증·DB 저장·LDAP 변경의 실제 구현 완료를 의미하지는 않는다.

### 1.1 확정된 방향

- 기존 ITAM의 사이드바, 흰색 화면, 분홍색 강조색, 카드·표·상세 모달 디자인을 유지한다.
- 관리자 영역은 `/admin`, 직원 영역은 `/portal`로 분리한다.
- 관리자 홈에서 티켓 정보를 즉시 확인하고 해당 업무 목록으로 이동한다.
- 직원 영역에는 본인 자산과 본인 요청을 표시한다.
- 자산과 티켓을 양방향으로 연결한다.
- Python으로 개발하며 FreeITSM은 기능·업무 흐름을 참고한다.

### 1.2 명세 적용 방식

- **목업 기준**: 현재 링크에서 확인하는 배치·메뉴·대표 상호작용.
- **구현 요구사항**: 실서비스에서 충족해야 할 검증·저장·권한·예외 처리.
- **후속 확정**: 아직 결정되지 않은 정책. 구현 시 기본값을 임의로 확정하지 않는다.

목업의 가상 직원 이름·자산 수량·티켓 번호·기준일은 화면 예시다. 실서비스에 고정 값으로 사용하지 않는다.

## 2. 경로와 진입 정책

### 2.1 관리자 경로

| 경로 | 화면 ID | 화면 | 핵심 기능 |
| --- | --- | --- | --- |
| `/admin` | ADM-01 | 통합 운영 대시보드 | 티켓 업무·자산·조직 요약 |
| `/admin/tickets` | ADM-02 | 티켓 목록 | 큐·검색·상태 필터 |
| `/admin/tickets?ticket={번호}` | ADM-03 | 티켓 상세 | 대화·처리·관련 자산 |
| `/admin/assets` | ADM-04 | 자산 현황·목록 | 기존 통계·검색·목록·등록 |
| `/admin/analysis` | ADM-05 | 분석·점검 | 기존 자산 분석과 확인 항목 |
| `/admin/maintenance` | ADM-06 | 전산 유지보수 | 계약·비용·갱신·SW 대장 |
| `/admin/organizations` | ADM-07 | 사용자·조직 | 조직도·직원·배정 자산 |
| `/admin/settings` | ADM-08 | 시스템 설정 | 계정·LDAP·운영 설정 |

### 2.2 직원 경로

| 경로 | 화면 ID | 화면 | 핵심 기능 |
| --- | --- | --- | --- |
| `/portal` | EMP-01 | 직원 홈 | 내 자산·내 요청 요약·요청 등록 |
| `/portal/requests` | EMP-02 | 내 요청 | 본인 요청 목록 |
| `/portal/requests?ticket={번호}` | EMP-03 | 내 요청 상세 | 공개 대화·진행 상태·답변 |
| `/portal/assets` | EMP-04 | 내 자산 | 본인 배정 자산·문제 신고 |

지원 요청 등록과 자산 상세는 현재 목업처럼 모달로 제공한다. 새로고침이 필요한 티켓 상세는 URL로 식별한다. 모달의 URL 표현은 추후 확정할 수 있다.

### 2.3 공통 경로·기존 경로 호환

| 대상 | 구현 요구사항 |
| --- | --- |
| `/` | 인증 확인 후 역할별 기본 화면으로 이동 |
| `/login` | 로그인 후 허용된 원래 경로 또는 기본 화면으로 이동 |
| 기존 `/admin` | 기존 설정 페이지에서 통합 대시보드로 역할 변경. 설정은 `/admin/settings`로 이동 |
| 기존 `/users` | 권한 검사 후 `/admin/organizations`로 이동 |
| 기존 `/manage/a/{UUID}` | 자산 관리 상세 연결 유지 또는 동일 자산의 새 관리 주소로 이동 |
| 기존 `/a/{UUID}` | QR 단건 조회 주소 유지. 공개 필드 제한 유지 |

- 경로 직접 입력, 새로고침, 뒤로·앞으로 가기에서도 동일 화면을 복원한다.
- 경로 분리는 권한 검사의 대체 수단이 아니다. API가 역할·법인 범위·본인 여부를 검사한다.
- 관리 권한이 없는 직원이 관리자 경로를 열면 접근 불가 화면과 직원 홈 이동 버튼을 제공한다.
- 존재하지 않는 티켓과 권한 없는 티켓은 다른 사람의 정보가 드러나지 않도록 일반적인 조회 불가 메시지를 제공한다.
- 관리자와 직원 역할을 모두 가진 계정의 기본 진입 정책은 후속 확정한다. 접근 가능한 영역 전환은 명시적으로 제공한다.

## 3. 공통 디자인과 레이아웃

### 3.1 디자인 기준

기존 `public/index.html`의 최종 적용 스타일을 기준으로 한다. 새 화면에 별도의 색상 체계나 새로운 브랜드를 도입하지 않는다.

| 요소 | 기준 |
| --- | --- |
| 글꼴 | 맑은 고딕, 시스템 한글 글꼴, sans-serif |
| 기본 본문 | 약 15px, 줄 높이 1.55 |
| 페이지 제목 | 데스크톱 약 28px, 모바일 약 24px |
| 강조색 | 기존 `--brand: oklch(0.6 0.25 15)` |
| 연한 강조 배경 | 기존 `--brandSoft: oklch(0.6 0.25 15 / .08)` |
| 기본 배경 | 흰색 및 기존 연한 중립 배경 |
| 테두리 | 기존 `--edge: oklch(0.92 0.004 286.32)` |
| 카드 | 흰색, 얇은 테두리, 약 11~14px 모서리 |
| 기본 버튼 | 분홍색 배경, 흰색 글자, 약 10px 모서리 |
| 보조 버튼 | 연한 회색 배경, 진한 회색 글자 |
| 상태 표시 | 텍스트와 배지 색상을 함께 사용 |
| 모달 | 흰색, 둥근 모서리, 배경 차폐, 닫기·취소 제공 |

색상·크기는 기존 화면을 구현 기준으로 삼는다. 새 아이콘은 의미를 나타내는 텍스트 또는 접근성 이름을 함께 제공한다.

### 3.2 관리자 공통 프레임

- 왼쪽 고정 사이드바: 기본 폭 256px, 중간 화면에서 220px.
- 상단 헤더: BUMJIN / IT WORKSPACE, 현재 영역 설명, 새로고침.
- 사이드바 제목: IT 통합 운영.
- 공통 빠른 작업: 티켓 등록.
- 본문: 최대 폭 약 1400px, 기본 안쪽 여백 28px.
- 현재 메뉴는 기존 분홍색 활성 스타일로 표시한다.
- 페이지 제목과 설명, 우측 주요 작업, 본문 순서로 배치한다.

관리자 메뉴:

1. 워크스페이스: 통합 대시보드, 티켓 관리.
2. 자산 관리: 자산 현황·목록, 분석·점검, 전산 유지보수.
3. 조직 및 운영: 사용자·조직, 시스템 설정.

### 3.3 직원 공통 프레임

기존 스타일을 공유하되 전용 제목·메뉴·작업을 사용한다.

- 제목: 직원 포털.
- 헤더: BUMJIN / EMPLOYEE SERVICE.
- 메뉴: 홈, 지원 요청, 내 요청, 내 자산.
- 기본 작업: 지원 요청.
- 하단 사용자 정보: 본인 이름·역할.
- 자산 등록, 조직 편집, LDAP, 내부 처리 메뉴는 표시하지 않는다.

현재 목업의 ‘관리자 화면 미리보기 / 직원 화면 미리보기’ 링크는 검토용이다. 실서비스에서는 양쪽 권한이 있는 사용자에게만 영역 전환을 제공한다. 목업 안내 배너와 NEW 표시는 실서비스 기본 화면에서 제거한다.

## 4. ADM-01 통합 운영 대시보드

### 4.1 화면 목적

메인 화면에서 티켓의 상태를 파악하고 우선 처리할 업무로 진입한다. 자산·조직 정보를 함께 제공하되 티켓 작업보다 먼저 노출하지 않는다.

### 4.2 영역 배치

```text
IT OPERATIONS OVERVIEW
통합 운영 대시보드                 [자산 등록] [티켓 등록]

[진행 중 티켓] [미배정 티켓] [기한 초과] [답변 대기]

[지금 처리할 업무                 ] [티켓 처리 현황       ]

[최근 접수 · 진행 요청                          전체 보기]

[IT 자산 현황                    ] [조직 · 직원 확인      ]
```

### 4.3 상단 지표

| 지표 | 집계 기준 | 클릭 동작 |
| --- | --- | --- |
| 진행 중 티켓 | 접수·처리 중·요청자 답변 대기·외부 업체 대기 | 전체 목록의 미종료 범위로 이동 |
| 미배정 티켓 | 미종료이고 개인 담당자가 없는 요청 | 미배정 큐 |
| 기한 초과 | 미종료이고 목표 처리일이 지남 | 기한 초과 큐 |
| 답변 대기 | 요청자 답변 대기 상태 | 답변 대기 큐 |

- 집계 범위는 현재 사용자가 볼 수 있는 법인·팀이다.
- 지표·큐·목록은 동일한 데이터와 필터 기준을 사용한다.
- 외부 업체 대기는 요청자 답변 대기와 구분한다.
- 목표 처리일이 없는 티켓은 기한 초과로 계산하지 않는다.
- 카드 전체를 클릭할 수 있고 키보드로 선택할 수 있다.
- 0건도 표시하며 클릭 시 정상적인 빈 목록을 보여준다.
- 목업의 ‘전체’ 큐 연결은 대표 흐름이다. 실서비스의 진행 중 카드에는 미종료 필터를 명시적으로 적용한다.

### 4.4 지금 처리할 업무

표시 우선순위:

1. 목표 처리일을 지난 요청.
2. 담당자가 없는 요청.
3. 내가 맡은 미종료 요청.

각 행은 아이콘, 업무 제목, 건수·대표 요청 제목, 이동 화살표로 구성한다. 항목을 누르면 해당 큐로 이동한다. 여러 업무를 중복 충족하는 티켓은 각 항목에 포함될 수 있으며 항목별 수치를 합산한 총계로 표현하지 않는다.

모든 항목이 0건이면 ‘현재 확인이 필요한 티켓이 없습니다’를 표시한다.

### 4.5 티켓 처리 현황

- 상태별 건수와 가로 막대를 표시한다.
- 막대는 색상뿐 아니라 상태명·건수를 함께 제공한다.
- 접수, 처리 중, 요청자 답변 대기, 외부 업체 대기, 해결, 종료, 취소의 실제 활성 상태를 기준으로 한다.
- 상태를 누르면 동일 상태 필터가 적용된 목록으로 이동한다.
- 분모는 동일 범위의 전체 티켓 수다. 0건이면 비율 계산을 생략한다.

### 4.6 최근 접수·진행 요청

| 열 | 표시 내용 |
| --- | --- |
| 요청 내용 | 제목을 주 정보로, 티켓 번호를 보조 정보로 표시 |
| 요청자 | 이름·요청 당시 부서 |
| 상태 | 상태 배지 |
| 우선순위 | 텍스트 배지 |
| 담당자 | 이름 또는 미배정 |
| 접수 | 날짜·시각 |

- 기본 최신 접수순, 최대 6건 표시.
- 행 클릭 시 티켓 상세로 이동.
- 전체 보기 클릭 시 티켓 목록.
- 긴 제목은 목록에서 줄임 처리하되 상세에서 전체 확인 가능.

### 4.7 자산·조직 요약

| 영역 | 항목 | 연결 |
| --- | --- | --- |
| IT 자산 현황 | 전체·사용·수리·보관 | 자산 현황·목록 |
| 조직·직원 | 직원 수·조직 수·사용자 미배정 자산 | 사용자·조직 |
| 이동·퇴사 확인 | 자산 회수·담당 티켓 재배정 확인 | 직원 상태 변경 확인 |

목업은 법인까지 포함한 조직 노드 수를 표시한다. 실서비스에서도 조직 수의 포함 범위를 동일하게 정의하고 설명한다. 직원 수는 기본 재직자를 기준으로 하며 전체·퇴사자 포함 조회는 별도로 제공한다.

## 5. ADM-02 티켓 목록

### 5.1 구성

- 제목·설명·티켓 등록 버튼.
- 전체·진행 중·미배정·답변 대기 지표.
- 큐 탭: 전체, 내 티켓, 미배정, 처리 중, 답변 대기, 기한 초과, 해결·종료.
- 검색·상태·담당 팀 필터.
- 티켓 표와 결과 수·페이지 이동.

### 5.2 필터 정의

| 큐 | 조건 |
| --- | --- |
| 전체 | 접근 가능한 전체 요청 |
| 내 티켓 | 본인이 담당하는 미종료 요청. 완료 포함 옵션 제공 가능 |
| 미배정 | 미종료이며 개인 담당자 없음 |
| 처리 중 | 처리 중 상태 |
| 답변 대기 | 요청자 답변 대기 |
| 기한 초과 | 미종료·목표 처리일 초과 |
| 해결·종료 | 해결 또는 종료 |

검색은 번호·제목·요청자·부서를 대상으로 한다. 큐·검색·상태·팀 필터는 AND로 결합한다. 활성 필터를 명시하고 초기화 버튼을 제공한다. 목업의 팀 선택은 샘플 단일 팀이며, 실서비스에서는 실제 큐 필터로 작동해야 한다.

검색·필터·페이지는 URL 쿼리 또는 동등한 복원 가능한 상태로 유지한다. 상세에서 돌아오면 기존 조건과 스크롤 위치를 복원한다.

## 6. ADM-03 티켓 상세

### 6.1 구성

| 위치 | 내용 |
| --- | --- |
| 상단 | 번호·접수 시각·제목·상태·우선순위·기한 초과 배지·목록 복귀 |
| 왼쪽 주 영역 | 요청 본문, 공개 대화, 내부 메모, 답변 입력, 처리 이력 |
| 오른쪽 보조 영역 | 요청자·소속·지원팀·담당자·상태·우선순위·관련 자산 |
| 주요 작업 | 내가 인수, 해결 처리 |

### 6.2 공개 답변·내부 메모

- 입력 전에 공개 범위를 선택한다. 기본값은 공개 답변.
- 내부 메모는 별도 배경·‘내부 메모’ 제목으로 구분한다.
- 공개 범위가 바뀌어도 작성 중 본문을 지우지 않는다.
- 빈 내용은 저장하지 않는다.
- 저장 중 중복 제출을 차단하고 실패 시 내용을 유지한다.
- 작성자·시각·수정 여부를 표시한다.
- 직원 API에는 내부 메모와 내부 첨부를 포함하지 않는다.
- 목업의 고정 내부 메모는 예시이며 실서비스에서는 저장된 기록만 표시한다.

### 6.3 담당자 인수

‘내가 인수’를 누르면 지원팀을 유지하고 개인 담당자를 현재 사용자로 지정한다. 접수 상태라면 처리 중으로 변경한다. 이미 다른 담당자가 처리 중이면 변경 사실을 알리고 필요한 권한·확인을 거친다. 이미 본인이 담당하면 중복 이력을 생성하지 않는다.

목업은 인수 버튼을 통한 대표 흐름을 제공한다. 실서비스는 팀·담당자·우선순위 변경 제어도 상세에 제공하며 변경 이력을 남긴다.

### 6.4 해결 처리

1. 해결 처리 모달을 연다.
2. 해결 내용을 필수 입력한다.
3. 저장 후 상태·대화·처리 이력과 대시보드 집계를 갱신한다.
4. 자산 상태는 자동으로 변경하지 않는다.

해결과 종료를 구분한다. 직원 해결 확인·담당자 종료·재개는 PRD 정책에 따라 제공한다. 현재 목업은 해결까지의 대표 흐름이며 자동 종료는 제공하지 않는다.

### 6.5 관련 자산

자산명·관리번호·현재 사용자와 상세 보기 버튼을 제공한다. 여러 자산 연결을 지원해야 한다. 미연결 티켓은 ‘연결된 자산 없음’을 표시한다. 링크만으로 자산 수정 권한을 부여하지 않는다.

## 7. ADM-04 자산 현황·목록·상세

### 7.1 기존 화면 유지

- 기존 자산 통계·도넛 차트·분석·사업부 탭·PC/모니터 탭을 유지한다.
- 검색, 사업부, 장비, 상태, 점검 항목 필터를 유지한다.
- 관리번호·소속·사용자·장비·사양·상태·노후 등급 표를 유지한다.
- 자산 등록·수정·확인·배정·반납·QR·라벨 출력을 기존 권한에 따라 제공한다.

기존 자산 상태 명칭 ‘사용·보관·수리’는 보존한다. PRD의 ‘사용 중·재고·수리 중’과 같은 의미로 매핑하되 화면과 저장값을 혼용하지 않는다. 최종 표시 명칭은 마이그레이션 설계에서 확정한다.

### 7.2 상세 추가 영역

기존 자산 상세 모달의 장비 정보·소프트웨어·QR·이력 아래에 **관련 티켓** 영역을 추가한다.

- 티켓 번호·제목·상태를 표시한다.
- 티켓 선택 시 상세 모달을 닫고 해당 관리자 티켓 상세로 이동한다.
- ‘이 자산으로 지원 요청’은 자산이 미리 선택된 등록 모달을 연다.
- 관련 티켓이 없으면 안내와 요청 등록 버튼을 표시한다.
- 직원에게는 별도의 읽기 전용 자산 상세를 사용한다.

## 8. ADM-05~08 분석·유지보수·조직·설정

### 8.1 분석·점검

기존 사업부별 장비, 사용 상태, 장비 구성, 확인 필요 자산, SW 기재 현황, 사용자별 자산, 최근 확인을 유지한다. 카드 클릭 시 해당 자산 필터로 연결한다. 관리자 홈의 티켓 통계와 자산 분석을 혼합하지 않는다.

### 8.2 전산 유지보수

기존 계약 항목·만료 예정·만료·비용 합계, 계약 검색·편집, 추가 SW 대장 조회를 유지한다. 공용 셀·대표 행 편집 등 기존 데이터 제약을 표시한다.

### 8.3 사용자·조직

- 왼쪽 조직 트리, 오른쪽 선택 조직의 정보·검색·직원 카드 구성 유지.
- 조직 검색, 펼치기·접기, 구성원 표시, 조직 추가·편집 제공.
- 직원 카드에서 계정·이메일·소속·배정 자산을 확인한다.
- 직원 검색·소속 필터·선택 상태를 표시한다.
- LDAP 부서 변경은 미리보기 후 적용하며 성공·실패·확인 필요를 구분한다.

추가 ‘직원 이동·퇴사 확인’ 모달:

| 요소 | 동작 |
| --- | --- |
| 직원 선택 | 현재 소속·배정 자산·담당 중 미종료 티켓 표시 |
| 처리 유형 | 부서 이동 또는 퇴사 |
| 변경 소속 | 부서 이동 시 입력, 퇴사 시 불필요한 입력 숨김 |
| 변경 미리보기 | 이전·이후 소속, 회수 대상 자산, 재배정 대상 티켓 표시 |
| 실제 적용 | 정책·권한 확정 후 구현. 현재 목업은 미리보기만 제공 |

직원 이동으로 자산 소유 법인·관리 부서를 자동 변경하지 않는다. 퇴사 후에도 기록을 보존하고 회수·재배정 미완료 항목을 추적한다.

### 8.4 시스템 설정

기존 관리자 비밀번호·LDAP 설정은 `/admin/settings`에서 제공한다. 개인 계정·역할·법인 범위 설정은 PRD에 따라 확장할 영역이며 현재 목업에서 완성된 화면으로 간주하지 않는다. 비밀번호·비밀키는 다시 표시하거나 감사 이력에 저장하지 않는다.

## 9. EMP-01 직원 홈

### 9.1 구성

- ‘내 자산 · 지원 요청’ 제목과 인사말.
- 주요 버튼: 지원 요청.
- 지표: 내 자산, 내 요청, 진행 중, 답변 대기.
- 내 IT 자산 카드.
- 내 요청 목록.

직원은 조직도·전사 자산·관리자 통계에 노출되지 않는다. 목업의 본인 정보 안내는 검토용이며 운영 화면에서는 자연스러운 제목·설명으로 대체한다.

### 9.2 주요 동작

| 작업 | 결과 |
| --- | --- |
| 지원 요청 | 요청 등록 모달 |
| 자산 상세 | 읽기 전용 자산 모달 |
| 자산에서 문제 신고 | 해당 자산을 자동 선택한 요청 등록 |
| 내 요청 선택 | 본인 티켓 상세 |
| 내 요청·내 자산 메뉴 | 각 전용 경로 이동 |

## 10. EMP-02~03 내 요청·상세

### 10.1 내 요청

본인이 요청자인 티켓만 표시한다. 담당자 대리 등록 건도 본인이 요청자라면 포함한다. 등록자와 요청자를 혼동하지 않는다.

표시 항목은 제목·번호·상태·우선순위·담당자·접수 시각이다. 검색·상태 필터는 본인 범위 안에서만 적용한다. 검색·필터를 추가할 때 관리자용 팀 큐는 노출하지 않는다.

### 10.2 내 요청 상세

- 요청 내용, 공개 답변, 상태, 담당 팀·담당자, 관련 본인 자산을 표시한다.
- 답변 입력과 목록 복귀를 제공한다.
- 내부 메모, 내부 첨부, 담당자 인수, 관리자용 우선순위·상태 변경을 숨긴다.
- 다른 직원의 티켓 번호를 직접 입력해도 내용을 반환하지 않는다.
- 답변 대기일 때 직원이 해야 할 행동을 명시한다.
- 해결 상태에서는 해결 내용을 확인하고 해결 확인 또는 미해결 재개를 제공한다. 세부 종료 정책은 후속 확정한다.

직원용 문구는 ‘담당자 확인 중’, ‘답변이 필요합니다’처럼 현재 상태와 다음 행동을 설명한다. 관리자 저장 상태와의 매핑은 일관되게 유지한다.

## 11. EMP-04 내 자산

본인에게 현재 배정된 자산만 카드로 표시한다.

| 요소 | 내용 |
| --- | --- |
| 상태 | 기존 자산 상태 배지 |
| 주 정보 | 제조사·모델 |
| 보조 정보 | 관리번호·관리 부서 |
| 상세 보기 | 읽기 전용 상세 모달 |
| 문제 신고 | 자산 자동 선택 요청 등록 |

직원 상세에는 관리번호·장비·배정 사용자·소속·상태·필요 사양을 제공한다. 자산 등록·수정·사용자 변경·수거·폐기·라벨 일괄 출력은 제공하지 않는다. 반환한 자산은 현재 목록에서 제외하며 과거 티켓 연결은 유지한다.

## 12. 공통 지원 요청 등록 모달

| 필드 | 관리자 | 직원 | 검증 |
| --- | --- | --- | --- |
| 제목 | 입력 | 입력 | 필수, 공백만 입력 불가 |
| 요청자 | 접근 범위 내 직원 선택 | 본인 고정 | 로그인 정보로 서버 확정 |
| 유형 | 장애·서비스 요청·문의 | 동일 | 필수 |
| 카테고리 | PC·주변기기, 계정·권한, SW, 네트워크, 기타 | 동일 | 필수 |
| 관련 자산 | 권한 범위의 자산 | 본인 자산 | 선택, 연결 권한 확인 |
| 상세 내용 | 입력 | 입력 | 필수 |
| 담당 팀·우선순위 | 운영 정책에 따라 설정 | 원칙적으로 숨김 | 기본 접수 규칙 적용 |
| 첨부 | 파일 선택 | 파일 선택 | PRD 크기·형식·권한 적용 |

첨부는 PRD 요구사항이며 현재 목업에는 파일 업로드가 구현되지 않았다. 다중 자산 선택도 실서비스 확장 대상이다.

### 12.1 제출 처리

1. 필수값을 검사하고 해당 필드 아래 오류를 표시한다.
2. 제출 중 버튼을 비활성화하고 중복 요청을 방지한다.
3. 성공 시 생성 번호를 알리고 티켓 상세로 이동한다.
4. 실패 시 입력을 유지하고 재시도할 수 있게 한다.
5. 취소·닫기 시 미저장 내용이 있으면 확인한다.
6. 직원 등록 후에는 직원용 상세 경로로 이동한다.

입력 길이와 첨부 형식의 최종 제한은 API 설계에서 확정하고 화면·서버 검증을 일치시킨다. 직원의 일반 문의는 자산 미연결 상태로도 등록 가능해야 한다.

## 13. 상태·알림·예외 처리

### 13.1 배지

| 구분 | 표현 |
| --- | --- |
| 접수·미배정 | 중립 배경 + 텍스트 |
| 처리 중 | 연한 파랑 + 텍스트 |
| 요청자·업체 대기 | 연한 노랑 + 각 대기 사유 텍스트 |
| 해결·종료 | 연한 초록 + 텍스트 |
| 기한 초과·높은 우선순위 | 연한 붉은색 + 텍스트 |

우선순위와 상태는 별도 열·라벨로 표시한다. 색상만으로 의미를 전달하지 않는다.

### 13.2 공통 상태

| 상황 | UI 동작 |
| --- | --- |
| 최초 로딩 | 카드·목록 로딩 표시, 0건으로 오인하지 않도록 처리 |
| 데이터 없음 | ‘등록된 요청이 없습니다’ 및 요청 등록 행동 |
| 검색 결과 없음 | 현재 조건 안내와 필터 초기화 |
| 부분 조회 실패 | 실패 영역 내 오류·재시도, 성공 영역은 유지 |
| 저장 중 | 중복 클릭 방지, 진행 상태 표시 |
| 저장 성공 | 짧은 완료 알림과 관련 영역 갱신 |
| 저장 실패 | 입력 보존, 원인·재시도 안내 |
| 동시 수정 충돌 | 최신 값 비교·새로고침 안내, 조용한 덮어쓰기 금지 |
| 인증 만료 | 재로그인 안내, 허용된 원래 경로 복귀 |
| 권한 없음 | 일반적인 접근 불가 메시지와 홈 이동 |
| LDAP 부분 실패 | 사용자별 성공·실패·확인 필요·미처리 표시 |

일반 성공은 토스트, 입력 오류는 필드 아래, 전체 오류는 페이지·패널 내 메시지로 표시한다. 중요한 실패를 자동으로 사라지는 토스트만으로 알리지 않는다.

### 13.3 알림

PRD의 앱 내 알림은 배정, 공개 답변, 상태 변경을 중심으로 제공한다. 알림 클릭 시 역할에 맞는 상세 경로로 이동한다. 내부 메모 내용은 직원 알림에 포함하지 않는다. 현재 목업의 통합 알림함은 후속 화면 설계 대상이다.

## 14. 반응형·접근성

| 화면 폭 | 레이아웃 |
| --- | --- |
| 1050px 초과 | 기본 사이드바, 다열 카드·주/보조 영역 |
| 801~1050px | 축소 사이드바, 대시보드·티켓 상세 세로 배치 |
| 800px 이하 | 사이드바 숨김, 메뉴 버튼·배경 차폐로 열기 |

- 키보드로 메뉴·지표·목록·모달을 조작할 수 있어야 한다.
- 모달 진입 시 포커스 이동, 모달 내 포커스 유지, 닫은 뒤 실행 버튼으로 복귀한다.
- Escape로 닫기와 미저장 확인 정책을 일관되게 적용한다.
- 제목·레이블·버튼에 적절한 접근성 이름을 제공한다.
- 행 전체 클릭 외에도 제목 링크를 제공해 키보드·새 탭 열기를 지원한다.
- 기본 터치 영역은 최소 44px을 목표로 한다.
- 상태·오류·알림은 스크린리더가 인지할 수 있게 처리한다.
- 글자 크기·확대 시 잘림과 가로 넘침을 점검한다.

## 17. 구현·검수 체크리스트

### 17.1 경로·진입

- [ ] `/admin`은 시스템 설정이 아닌 통합 대시보드다.
- [ ] `/portal`은 직원 메뉴만 표시한다.
- [ ] 경로 직접 접근·새로고침·뒤로 가기가 동작한다.
- [ ] 티켓 상세 URL로 동일 티켓을 복원한다.
- [ ] 기존 QR UUID와 관리 상세 연결이 유지된다.
- [ ] 역할·범위에 맞지 않는 경로와 API 접근이 차단된다.

### 17.2 관리자 업무

- [ ] 홈에서 진행 중·미배정·기한 초과·답변 대기를 확인한다.
- [ ] 카드 수치와 클릭 후 목록 수치가 일치한다.
- [ ] 담당자 인수·해결 후 지표와 목록이 갱신된다.
- [ ] 내부 메모와 공개 답변이 명확히 구분된다.
- [ ] 자산에서 티켓, 티켓에서 자산으로 이동한다.
- [ ] 자산·유지보수·조직의 기존 기능이 유지된다.

### 17.3 직원 업무

- [ ] 본인 요청·배정 자산만 조회한다.
- [ ] 다른 직원 티켓 번호를 입력해도 내용이 노출되지 않는다.
- [ ] 내부 메모·내부 첨부·관리자 작업이 노출되지 않는다.
- [ ] 자산 문제 신고 시 본인과 해당 자산이 자동 선택된다.
- [ ] 자산 없이 일반 문의를 등록할 수 있다.
- [ ] 요청 답변과 해결 확인 흐름을 완료할 수 있다.

### 17.4 품질

- [ ] 빈 상태·조회 실패·저장 실패·충돌을 구분한다.
- [ ] 실패·검증 오류 시 입력을 보존한다.
- [ ] 중복 제출을 방지한다.
- [ ] 모바일 카드형 목록과 모달을 확인한다.
- [ ] 키보드·포커스·접근성 이름을 확인한다.
- [ ] 샘플 데이터·목업 전환 링크·NEW 배너를 운영 배포에서 제거한다.

## 18. 후속 확정 사항

1. 로그인 방식과 다중 역할 계정의 기본 진입·영역 전환 정책.
2. 개인별 역할·법인·팀 범위 및 시스템 관리자의 업무 열람 범위.
3. 티켓 목표 처리일 기본 규칙, 대기 상태의 SLA 처리.
4. 직원 해결 확인·종료·재개 정책.
5. 최종 자산 상태 표시명과 기존 원장 값 매핑.
6. 입력 길이·첨부 형식·건수·보존 기간.
7. 알림함, 계정·권한 설정, 다중 자산·첨부의 상세 화면.
8. 조직·LDAP·직원 소속의 원본 정책과 실제 이동·퇴사 적용 절차.
